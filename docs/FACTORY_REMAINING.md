Актуально на 16 ноября 2026. Windows исключён пользователем. Telegram и VK можно подключить позже через «Аккаунты» — формы и инструкции уже есть. Подключение аккаунта и разрешение на тестовую публикацию — отдельные действия.

## 1. Что действительно нужно дописать

### Загрузка VK Клипов

Готового отправителя VK сейчас нет. Есть подключение статистики, привязка уже опубликованного ролика и сбор доступных счётчиков через `video.get`. Это не даёт загрузку нового Клипа.

Осталось:

1. Проверить доступный загрузчик в настоящем тестовом аккаунте. Метод `shortVideo.create` официально не подтверждён, поэтому на нём нельзя строить рабочую интеграцию. Общий браузерный драйвер уже есть; нужен проверенный контракт именно VK.
2. Реализовать загрузку файла, передачу подписи, подтверждение результата и сохранение действительного ID/ссылки.
3. Подключить VK к целям канала, выходным параметрам ролика, календарю, лимитам, истории и аналитике.
4. Проверить потерю связи, капчу, истёкший вход и перезапуск: неизвестный результат должен требовать ручной проверки, повторная отправка не должна создавать дубль.
5. Пройти изолированные тесты и затем согласованный сценарий с настоящим аккаунтом.

Пользователь отложил VK-подключение. Сейчас доступа к загрузчику нет; нельзя честно объявить эту часть завершённой или выдать придуманные селекторы за проверенный адаптер.

## 3. Дополнительные сигналы и аналитика

- **Клипы зрителей Twitch:** клиент Helix и настройки уже есть. Нужны бесплатные Client ID/Secret приложения Twitch, чтобы проверить получение клипов и привязку по `vod_offset`. Обычная обработка VOD и чата уже проверена отдельно и не зависит от этих ключей.
- **Автоматическая статистика TikTok:** нужен доступ приложения к Display API и разрешению `video.list`. Вход через браузер такого API-доступа не даёт. По исходному ТЗ при отсутствии допуска автосбор пропускается; ручной ввод метрик уже предусмотрен.
- **Telegram:** универсальных просмотров через Bot API нет; ручные значения остаются предусмотренным способом. Дополнительные модели для этого не нужны.
- **Рекомендации весов анализа:** механизм проверен на синтетической истории; для полезных рекомендаций по своему каналу нужно накопить минимум 50 роликов и подходящие замеры примерно через 48 часов. Ждать этого для локального монтажа не требуется.

## 4. Реклама: нужны материалы и проверка результата

Кампании, ротация, даты и лимиты, UTM/промокоды, баннеры с хромакеем/альфой, отчёты HTML/CSV и печать уже работают в изолированных сценариях.

Осталось выбрать настоящий баннер, ссылку и промокод, если они нужны, затем посмотреть готовый ролик с этим баннером: размер, читаемость, положение и момент появления. Для отчёта нужно проверить, подходят ли текущие колонки и оформление; образец рекламодателя требуется только при наличии особых требований. По результату при необходимости дорабатывается шаблон или отчёт.

## 5. Финальная проверка целой фабрики

После подключения выбранных площадок и отдельного разрешения на конкретные тестовые публикации:

1. Настоящий источник → обнаружение → анализ → нарезка → шаблон/баннер → Inbox или auto.
2. Пакетное одобрение → календарь → реальные публикации по слотам на проверенных площадках.
3. Контролируемый перезапуск во время работы → сохранённые задачи и отсутствие дублей.
4. Получение доступных метрик → сверка ссылок, истории и отчёта двух кампаний.

Восьмичасовая изолированная приёмка уже завершена: 28 849 секунд, 958 опросов, 4 источника, 8 тестовых ответов публикации. Она использовала настоящую обработку медиа и поддельные внешние сервисы; поздние изменения проверялись отдельно. Повторно запускать её для ответа на этот вопрос не нужно.

## Что уже можно проверять локально

Источники и мониторинг, скаут, чат, ручные границы, поиск лица и раскладка A «круг + геймплей», шаблоны, рендер, QC, пакетное одобрение, календарь, кампании, отчёты, ручные метрики, восстановление, диск и запрет сна Linux. Текст подписи необязателен: общий, свой для каждого или пустой; локальная генерация хэштегов сохранена.

Последний полный Rust-прогон: **454 успешно, 0 ошибок, 21 пропущен**. TypeScript, сборка и реальные изолированные окна со скриншотами проверены. Это состояние кода в проекте; установленное приложение не обновлялось. Полная v1.0 ещё не завершена, выпуск выполняется только по отдельному указанию.

## Порядок продолжения

1. Подключить первую готовую площадку и проверить её реальные права/ограничения.
2. Когда пользователь вернётся к VK — исследовать загрузчик и закончить адаптер.
3. Проверить остальные выбранные площадки, свой баннер и отчёт.
4. Провести согласованную живую сквозную приёмку, затем принять решение о версии и установке.
