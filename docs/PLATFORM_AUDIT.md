## Метрики, 15.11.2026

- YouTube: [videos.list](https://developers.google.com/youtube/v3/docs/videos/list) с `part=statistics,snippet`; [Video resource](https://developers.google.com/youtube/v3/docs/videos) содержит `viewCount`, `likeCount`, `commentCount`. Отсутствующий счётчик не равен нулю. Владелец сверяется по `snippet.channelId` с подключённым аккаунтом. Прежний OAuth уже запрашивает `youtube.readonly`. У Shorts с 31.03.2025 просмотры означают запуски/повторные запуски; это счётчик площадки, не уникальные зрители.
- Instagram: [IG Media Insights](https://developers.facebook.com/docs/instagram-platform/instagram-graph-api/reference/ig-media/insights/) подтверждает `views`, `likes`, `comments`, `shares` и необходимость `instagram_manage_insights` для Facebook Login. При неподходящих правах выводится ошибка доступа; отсутствующие значения не заменяются нулями. Доступ к Reels проверяется по `owner.id`. Сбор зависит от типа медиа, прав приложения и допуска аккаунта; fake tests не подтверждают live-доступ.
- TikTok: [Video Query](https://developers.tiktok.com/doc/tiktok-api-v2-video-query/) описывает `view_count/like_count/comment_count/share_count` и scope `video.list`. Допуск Display API конкретного приложения не предоставлен, браузерный аккаунт не даёт этот токен. Автосбор пропущен, доступен ручной ввод.
- Telegram: [Message](https://core.telegram.org/bots/api#message) и Bot API не предоставляют универсального чтения просмотров/истории произвольного сообщения канала. `sendVideo` receipt подтверждает отправку и ID, просмотры из него не выводятся. Доступен ручной ввод.
- VK: подключение профиля статистики и привязка уже опубликованного видео реализованы через `video.get`; ниже приведены контракт и граница изолированной проверки. Живая проверка токена и загрузчик VK остаются открытыми.

HTML-снимки всех перечисленных страниц сохранены в `.factory-tests/phase7/`. YouTube/Instagram читаются через GET, VK `video.get` — через POST form к официальным origin, с отключёнными redirect; loopback-подмена доступна в debug для изолированных проверок. Квоты/ошибки авторизации откладывают повтор по аккаунту и не вызывают повторной публикации.

## VK video.get — уточнение 16.11.2026

Официальный [VKCOM/vk-api-schema](https://github.com/VKCOM/vk-api-schema/tree/333481bd082ad747d4873ef4a77f9247097eeef0) подтверждает `video.get`: токен пользователя, параметр `videos` в формате `<owner_id>_<media_id>` (отрицательный владелец — сообщество), ответ `response.items` с `id`, `owner_id`, `views`, `likes.count`, `comments`, `reposts.count`. Версия схемы 5.199.99, используемая версия API 5.199. Пустой/недоступный ответ не подтверждает возможность получить статистику конкретного Клипа.

[Официальный PHP SDK](https://github.com/VKCOM/vk-php-sdk/blob/cf5b8d84440256e1595d067ef255cbc8e372eb0d/src/VK/Client/VKApiRequest.php) передаёт параметры, `v` и `access_token` в POST form к методу API. Для readonly `video.get` используется этот способ: токен остаётся вне URL, redirects отключены, тело/секреты ошибок наружу не передаются. Прежнее описание «только GET» относится к YouTube/Instagram; POST к `video.get` не отправляет видео и не меняет публикацию. Официальные JSON/SDK-снимок и provenance/SHA-256 сохранены в `.factory-tests/phase7/vk-schema/`.

Транспорт и общая синхронизация проверены: fake API (владелец/nullable/ошибки/лимиты/без redirect), настоящий Tauri/SQLite/Analytics, SIGKILL/restart и cooldown авторизации. Пользовательское подключение отдельно проверено через Аккаунты → токен в тестовую связку ключей → привязка draft/ready в Аналитике → первый замер и отчёт кампании; VK-аккаунты и публикации в этом сценарии не добавлялись напрямую в БД. Проверены локальная пауза без API, отказ записи токена, защита от дублей и одновременного сбора, перезапуск без повторного запроса. Полный Rust — 450 PASS/0 FAIL/21 ignored; native и Chromium снимки просмотрены. Живых запросов к VK с токеном и отправок не было. Живая проверка пользовательского токена и загрузчик VK остаются отдельными условиями готовности.
