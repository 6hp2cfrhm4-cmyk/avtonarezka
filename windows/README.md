# Автонарезка для Windows 11

Эта папка собирает установщик для Windows 11 с Linux-машины (кросс-компиляция). Код приложения общий: всё, что
отличается по ОС, собрано в [src-tauri/src/platform.rs](../src-tauri/src/platform.rs) и в нескольких `cfg(windows)`-ветках;
Linux-версия от этого не меняется.

## Что получается

`windows/release/`:

| Файл | Зачем |
| --- | --- |
| `Автонарезка_0.2.5_x64-setup.exe` | установщик NSIS без прав администратора: программа, воркер языковой модели, ffmpeg, ffprobe, yt-dlp, Deno |
| `fetch-models.ps1` | скачивает три модели (~3 ГБ) в `%LOCALAPPDATA%\app.avtonarezka.desktop\models`, проверяя размер файлов |
| `ИНСТРУКЦИЯ.txt` | короткая инструкция для того, кто будет ставить |
| `SHA256SUMS` | контрольные суммы |

Модели в установщик не входят (потолок NSIS около 2 ГБ), ставятся отдельным скриптом.

## Сборка

Один раз поставить (Arch):

```bash
sudo pacman -S lld ninja nasm wine scons mingw-w64-gcc mingw-w64-zlib   # wine нужен только для smoke-wine.sh
```

NSIS ставить не нужно: `windows/build-nsis.sh` сам собирает его из исходников в `windows/.cache/nsis`. Пакет `nsis` из AUR
собирается с `TARGET_ARCH=amd64` и делает только 64-битные установщики, а Tauri рассчитан на стандартный (x86) NSIS и его
32-битный плагин `nsis_tauri_utils.dll`. 32-битный установщик ставит обычное 64-битное приложение, на Windows 11 это норма.

Дальше всё делает один скрипт (первый запуск долгий: кэш Windows SDK ~1,2 ГБ, whisper.cpp и llama.cpp с нуля):

```bash
windows/build-windows.sh
```

Он по порядку: проверяет программы и ставит Rust-таргет и `cargo-xwin` (`setup-toolchain.sh`) → скачивает ffmpeg,
yt-dlp и Deno с проверкой SHA256 (`fetch-tools.sh`) → собирает воркер языковой модели → собирает запасной загрузчик
Vulkan (`build-vulkan-loader.sh`) → собирает приложение и установщик
(`tauri build --runner cargo-xwin --config windows/tauri.windows.conf.json`) → складывает результат в `windows/release/`.

Что настроено и почему:

- **Vulkan для Whisper и языковой модели.** Windows SDK Vulkan у нас нет, поэтому `setup-toolchain.sh` собирает заглушку в
  `windows/.cache/vulkan-sdk`: заголовки системы, `vulkan-1.lib` из списка экспорта загрузчика ([vulkan/vulkan-1.def](vulkan/vulkan-1.def),
  Khronos, Apache-2.0) и `glslc` хоста. Вторая библиотека `vulkan.lib` нужна из-за `whisper-rs-sys`: его build.rs проверяет ОС хоста,
  а не цели, и на Linux просит `-lvulkan`.
- **Запасной загрузчик Vulkan.** Обычно `vulkan-1.dll` кладёт в System32 драйвер видеокарты. На чистой Windows или в виртуалке её нет, и с
  обычным (статическим) импортом программа не запустилась бы вовсе. Поэтому `vulkan-1.dll` подключена с отложенной загрузкой
  (`/DELAYLOAD` в [build.rs](../src-tauri/build.rs) и [llm-worker/build.rs](../src-tauri/llm-worker/build.rs)), а [vulkan_loader.rs](../src-tauri/src/vulkan_loader.rs)
  перед первым обращением к видеокарте берёт системную DLL из System32, а если её нет, нашу из `vk\vulkan-1.dll` рядом с программой. Наш загрузчик
  без драйвера видит ноль видеокарт, и Whisper с языковой моделью работают на процессоре. `build-vulkan-loader.sh` собирает его из исходников Khronos
  (тег и коммит зафиксированы, версия равна версии `vulkan-headers`) через clang-cl со статическим CRT; кроме vulkan-1.dll там ничего не нужно.
  Лежит он именно в `vk\`, а не рядом с exe: рядом он перебил бы системный даже там, где драйвер стоит.
- **Статический CRT**: на чистой Windows 11 нет VC++ Redistributable, поэтому ни `avtonarezka.exe`, ни `llm-worker.exe` не импортируют
  `VCRUNTIME140`/`MSVCP140`/`ucrtbase`. Для этого нужны три вещи, и все три уже в скриптах: `-C target-feature=+crt-static` и
  `LLAMA_STATIC_CRT=1` (`windows/env.sh`); `CMAKE_POLICY_DEFAULT_CMP0091=NEW` и `CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded` там же
  (у whisper.cpp в CMake старая политика, и без них он собирается с `/MD` и не линкуется); явный `libucrt` в [build.rs](../src-tauri/build.rs)
  (математика `sin`, `pow` и др. лежит в `libucrt.lib`, а чисто Rust-зависимости вроде tract её не просят).
- **Путь к `vulkan.lib`** для whisper.cpp передаётся переменной `LIB` (`env.sh`): `whisper-rs-sys` из-за проверки ОС хоста сам путь не добавляет.
- **NSIS** собирается `windows/build-nsis.sh` (см. выше), потому что нужен 32-битный.
- **Папка `tools`.** `platform::find_tool` сначала ищет утилиты рядом с программой (`tools\ffmpeg.exe`, `yt-dlp.exe`, `deno.exe`), потом в PATH.
  Эта папка ставится в начало PATH дочерних процессов, поэтому yt-dlp находит там и ffmpeg, и Deno.
- **Установка в папку пользователя** (`installMode: currentUser`): не нужен UAC, и `yt-dlp.exe -U` может обновлять сам себя.
- **Секреты TikTok** лежат в Диспетчере учётных данных Windows (`tiktok/secrets.rs`, запись `avtonarezka/<ключ>`), как на Linux в связке ключей.
- **TikTok через браузер**: Chrome, Chromium или Edge (он есть в любой Windows 11).

Если сборка воркера падает с «No rule to make target…» или «CMake project was already configured» после неудачной попытки,
удали остаток: `rm -rf src-tauri/target/x86_64-pc-windows-msvc/release/build/llama-cpp-sys-2-*` (то же для `whisper-rs-sys-*`).

## Проверка

На этой машине (без Windows): `windows/smoke-wine.sh` запускает ffmpeg и воркер под Wine и проверяет, что фильтр субтитров
понимает путь вида `C:/Пробный каталог/…` (пробел и кириллица), и что в ffmpeg есть `h264_nvenc` и libass. Если на машине лежит
Qwen3-4B, прогоняется и воркер с настоящей моделью в двух режимах: с системным загрузчиком Vulkan (в Wine он есть, воркер идёт на
видеокарте) и без него и без драйверов (берётся запасной из `vk\`, воркер на процессоре). Окно приложения под Wine не проверить:
WebView2 там ненадёжен.

На настоящей Windows 11, по порядку:

1. Установщик запускается без прав администратора, в меню «Пуск» есть «Автонарезка», окно открывается.
2. Вверху окна ffmpeg и NVENC зелёные, yt-dlp зелёный и без пометки «нет Deno».
3. `fetch-models.ps1` докачал три модели; на экране «Анализ» нет пометок о пропущенных этапах.
4. «Импорт»: перетащить видео мышью, затем «Найти моменты». В выводе анализа речь и модель идут на видеокарте (быстро, как на Linux).
5. Черновики, затем финал: ролик рендерится, субтитры видны нужным шрифтом, «Открыть папку» открывает Проводник.
6. YouTube: вставить ссылку, скачать в 1080p; название с кириллицей и эмодзи не ломает путь.
7. TikTok: сохранить Client key/secret (проверить в «Диспетчере учётных данных» запись `avtonarezka/…`), войти по API.
8. Запасной загрузчик (нужна машина или виртуалка без драйвера видеокарты, например «Базовый видеоадаптер Microsoft»): программа
   запускается, а анализ идёт на процессоре (заметно медленнее видеокарты). Если проверить негде, это нормально: на машине с
   драйвером запасной путь не включается.
9. Если у пользователя кириллица в имени профиля Windows (`C:\Users\Алексей`), пройти пункты 4-6 именно под ним.

## Ограничения

- Установщик не подписан: Windows SmartScreen покажет «неизвестный издатель». Нужен сертификат подписи кода.
- Запасной загрузчик Vulkan проверен под Wine только в сценарии «драйверов нет» (воркер уходит на процессор и отвечает). В паре с драйвером
  он под Wine упал, поэтому и выбран порядок «сначала системная DLL»: там, где драйвер стоит, берётся системный загрузчик, как у любой
  программы с Vulkan. На настоящей Windows запасной путь не проверялся. Если папки `vk` нет и системной DLL тоже нет, первый же
  вызов Vulkan завершит программу (в журнале будет строка про `vk`).
- ffmpeg от BtbN распространяется под GPL; он запускается отдельным процессом. Лицензия и ссылки на исходники лежат в `tools\`.
- Обновления yt-dlp нужны регулярно (`yt-dlp.exe -U` в папке `tools`): YouTube меняется часто.
